"Age of Wonders X" is a community mod of Age of Wonders (1999, Delphi 3-era) maintained by binary-patching the shipped EXEs/DLLs — there is no source. Main binaries: AoWx.exe (game, fixed base 0x400000, NO .reloc), aowInt.dpl (the game's own widget toolkit, preferred base 0x59800000, HAS .reloc), AoWEPACK.dll (game logic), VCL30.dpl (Delphi VCL), AoWDevX.exe/HSEPack.dpl (map editor).

**Why:** All work is done as Python patch-builder scripts in `patch scripts\`.

**How to apply:** Follow the house pattern (see `build_wheel_aowint.py` as the canonical example): dry-run by default, `--apply` / `--revert` flags, backup to `<game>\backup\<relpath>.bak_<feature>` before first write — **since 2026-09-17 (user request: keep the game folder clean) backups go in the `backup\` subfolder of the game dir, mirroring subpaths (`backup\Dict\Release.mld.bak_frost`); use `from bakpath import bak_path; BAK = bak_path(target, ".bak_feature")` from `patch scripts\bakpath.py` (falls back to the legacy beside-the-file location for reading, so old backups still revert). The 25 active 410 scripts were rewritten to it and their 28 backups moved; the project-root's August `.bak_*` files were left where they are** — assert old bytes before patching, check .reloc entries don't intersect patched code caves. ⚠ **ALL DLLs/DPLs can be rebased at load time — AoWEPACK.dll was OBSERVED loaded at 0x2560000 instead of 0x55700000 (varies per launch)** — so cave code in ANY dll must be position-independent: rel32 calls are fine, but absolute data refs and VMT-pointer compares need the call/pop load-delta trick (normalize runtime pointers by subtracting delta before comparing to preferred-base constants). Only AoWx.exe addresses may be hardcoded (EXE always loads at 0x400000). ⚠ The game folder holds BOTH `AoWEPACK.dll` (loaded, patched, 2026-09) and `AoWEPACK.dpl` (old 2026-08-22 build, unpatched) — same for AoWTCPCK: always disassemble/patch the `.dll`; a `.dpl` analysis misses every applied cave (cost a wrong hook plan on 2026-09-16). Existing AoWEPACK caves that embed absolute addresses without reloc entries (worth auditing: healing/lifesteal/slaying family) silently break on rebased launches. Python 3.12 (`py`) with capstone 5.x is available for disassembly. ⚠ On the laptop (2026-09-12→09-18) the working game folder was a `410 prerelease` subfolder; **on the desktop since 2026-09-20 the project folder itself is the game dir again** (user's call: no subfolder) — scripts take `--dll`/`--game` and default to `bakpath.game_dir()` (AOW_GAME_DIR, else the parent of `patch scripts`). Never bake a machine path. ⚠ Writing a patched dll with `open(dll,'wb')` intermittently fails with `OSError [Errno 22] Invalid argument` on this desktop (timing/filter, not a lock) — use a same-size in-place `r+b` write (see `write_inplace` in patch_champion_leveled_ranged_v1.py); and NEVER probe writability with mode 'wb' (it truncates — done once, recovered from the .bak). Release changelog drafts live in `changelog_*.txt`; changes also go into X/Documentation/changelogs.txt at release time via `patch scripts\manual_build\build_manual_from_game.py`.
