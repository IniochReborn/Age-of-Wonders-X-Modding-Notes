**User report 2026-09-20:** AI defenders keep focusing Battering Ram / Turtle Ram / Bone Ram / Drill after the wall is breached. **BUILT + APPLIED the same day: `patch scripts/patch_ai_ram_focus_v1.py` (dry-run / --apply / --revert / --dis), hook 0x413673 -> cave 0x43A100-0x43A1DA (218 B, PIC), backup `backup/AoWTCPCK.dll.bak_ramfocus` (= state after AoO+melee+healing+rangedobs). Tunable RAM_VALUE_PCT = -100 (harmless crusher worth MINUS its vanilla value after the breach -> attacked last, still killed when nothing else is proposed). Harmless test = has Wall Crushing AND no unit-DV entry in its own target list; user said not to special-case the A.M.C. (it is caught as harmless now; a future melee replacement on that id gets a unit DV and drops out automatically). **Next free TCPCK cave 0x43A200.** IN-GAME TEST PENDING: siege with rams -> after the first wall section falls the AI defenders should switch to real units and only finish rams when nothing else is reachable; before the breach unchanged.**

**Root cause (AoWEPACK.dll):** a combat object's target value = `TCombatUnit.GetTargetStrength` 0x55725850 (VMT+0x5C; cached in [obj+0x40], dirty byte +0x44 set by TargetsChanged 0x557261AC) = `TCombatObject.GetTargetStrength` 0x55726454 = **average of entry.D over the object's target list [obj+0x10]** (TQuadItemList: +4 items, +8 count, 16-B entries A=target obj, B=CV, C=wallCV, D=DV) + CommandingTargetStrength (Leadership). The list is filled ONCE by `SetupTargets` 0x557264AC (callers: TCombat.Activate 0x557281A4, SetCombatPlayer 0x55726842) over every alive object of the opposing side — **for the attacker that includes the TCombatWall sections**. D = `GetTargetCVDV` 0x557252E8 = max over the unit's abilities of ability VMT+0xEC tcGetDamageValueEx(self, target). `TWallCrushingAbility.tcGetDamageValueEx` 0x557687C8 returns 0 unless `CanTouch` 0x55768968 (= target is NOT a TCombatUnit), so a ram's DV vs units is 0 and vs walls is StatisticsToLimitedDV(ram ATK/DMG…) > 0 ⇒ **a ram's whole value is wall potential, frozen at combat start**; nothing re-reads it after a breach. Giants/Elementals/Ents etc. also carry Wall Crushing (0x75) but have real unit DVs; harmless crushers = Battering Ram 250, Turtle Ram 64, Bone Ram 249, Drill 253, Guild Drill 262 (+ A.M.C. 286, transport only). Flame Thrower/Frost Blower Ram, Waste Spewer, Bomber (Self Destruct) are NOT harmless.

**Breach flag:** `TCombatWall.DestroyObject` 0x55725C64 sets `[[combat]+0xC]+0x4D = 1` (TCombatData +0x4C walls present, +0x4D breached) when ANY section dies (catapult/spell too). TCPCK reads it as `[[[0x46C064]+0xE4]+0xC]+0x4D` (ChargeFromPos 0x4137AE, touch pct 0x41721B). Vanilla already uses it for WALL targets: `TCombatWall.GetTargetStrength` 0x55725B54 = 10 intact / 1 breached / 0 dead, and touch pct 0xA vs walls after round 1 (0x41722F).

**Scoring path (AoWTCPCK.dll):** every attack type (melee cave 0x438B20→, ranged 0x417510, touch 0x416F6A, heal) calls `TCAI.tcDVtoDEV` 0x413664(cai, edx=ourDV, ecx=theirDV, [ebp+8]=TARGET, [ebp+0xC]=SELF) = (targetValue·[×2 hero][×2 leader]·ourDV − selfValue·[×2]·theirDV)/100; target value fetched at **0x413673 `mov eax,[ebp+8]; mov edx,[eax]; call [edx+0x5C]; mov [ebp-0x14],eax`** (bytes 8b45088b10ff525c8945ec — untouched by any patch; build_hero_melee_courage only edits imm8 at 0x413718/0x41373B, patch_ai_melee_vs_ranged calls 0x413664 from its cave). Rams never retaliate (theirDV=0) so hitting one is "free" positive value. Phase 4 (0x41A3FB) selection-sorts moves by +0xC desc WITHOUT dropping negatives; phase 5 executes list[0] ⇒ a negative value still works as a last resort when nothing else is proposed.

**Design as built:** 8-byte hook at 0x413673 → PIC cave (next free TCPCK cave 0x43A100): after the VMT+0x5C call, if `[data+0x4D]` breached AND target side ≠ self side AND target is TCombatUnit AND target is "harmless" — no entry in [target+0x10] whose A IsClass TCombatUnit (IAT 0x46E904) has D>0 (uses the game's own numbers; no ability tables; covers rams/drills/A.M.C. and mod units) — then value := 0 (or a negative sentinel such as −(selfValue) so rams rank below every real target but remain the fallback). Optional gate: [cai+4]==1 (defender only). Before the breach nothing changes (defenders still prioritise rams at the wall). Alternative rejected: zeroing Wall Crushing's DV at the ability level — cached at SetupTargets, never refreshed. Verification idea: read [obj+0x40] of every combat object from the live process during a siege (probe pattern as in patch_heal_ai_tcpck_v1 --read) to quantify ram value vs real units.
