Since 1.37.406 every release ships BOTH `upload\AoWx_1_37_<N>.zip` and `upload\AoWx Installer (version 1.37.<N>).exe`. Build order: release zip first ([[aowx-release-process]]), then `python "patch scripts\installer\build_installer.py" --ver <N>` — extracts the zip to temp staging, sanity-checks, compiles `patch scripts\installer\AoWxInstaller.iss` with ISCC, passing /DAppVer /DStagingDir /DGameDir /DOutDir /DOutName. Inno Setup 6.7.3 at `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`. Installer icon = `assets\aowx_installer.ico` (AoWx.exe dragon + gold gear badge, 4x-supersampled with hole punched through).

**Dark mode + burgundy theme:** `WizardStyle=modern dark includetitlebar` + `WizardStyleFile=assets\aowx_dark.vsf` + `WizardBackColor=#141414` + `WizardImageBackColor=#141414`; wizard_small.bmp background #141414; Discord link light blue $FFA64D (user preference). **aowx_dark.vsf built by `patch scripts\installer\make_style.py`**: extracts Inno's built-in dark style from SetupCustomStyle.e32 PE resource VCLSTYLE\WINDOWSMODERNDARK (format: 'VCL_STYLE 2.0' + zlib(inner); inner = UTF-16 metadata, 3 raw BGRA atlases style.png/style15x.png/style20x.png each [utf16 name][w:u32][h:u32][pixels], then ~300KB DFM-binary object tree + a color table stored as UTF-16 `Name` + `$00BBGGRR` STRING pairs — string values are safely patchable in place, same length). FOUR-tier pixel transform (hue 348°): strong blues → deep rich red (s*1.25, v*0.70); slate-teal family (b>r+12, b>g+4, b>55, r>30) → rich burgundy (s≥0.55, v*0.85); neutral control greys 40..100 (|r−g|,|g−b|<3) → subtle burgundy tint (s=0.38) = Cancel/normal buttons; **tier 4 (added 2026-08-23): the Next/default button's face is PREMULTIPLIED-alpha slate stored ~rgb(30,53,64) a≈170 as a tiny stretched 9-patch (~80 px/atlas!) — escapes tiers 1-3 (premult scales r below the r>30 gate); catch with b>r+8 & b≥g & b>35 → burgundy s≥0.55, v*1.12, clamp channels ≤ alpha.** String color table also patched (FocusEffect #B01E36 etc.). ⚠ Do NOT blind-recolor binary dwords in the tail — corrupts structure → "Integer overflow" at Setup start. Rerun make_style.py after any Inno upgrade. **Progress bar is a NATIVE msctls_progress32, not style-drawn, and it IGNORES SetWindowTheme(h,'','')+PBM_SETBARCOLOR (tried, stayed green)** — instead the iss HIDES ProgressGauge and draws its own bar: two stretched 1x1-bitmap TBitmapImages (track $202020, fill $361EB0 = #B01E36) whose fill width tracks ProgressGauge.Position via a 100ms SetTimer (StyleProgressBar/BarTimerProc; verified burgundy on screen 2026-08-23). Browse button repointed to BrowseForFolder starting at {userdesktop} (DirBrowseClick).

**⚠ Automation gotcha:** keybd_event modifier tricks can leave a STUCK modifier system-wide (a stuck Ctrl made the splash ignore ALL clicks/Enter — looked like broken input). Before UI-driving, release modifiers (keybd_event up for 0x10-0x12, 0xA0-0xA5). Working driver: scratchpad click_and_shoot.ps1 pattern.

**Testing gotcha:** splash art buttons (TBitmapImage.OnClick) do NOT respond to PostMessage'd WM_LBUTTONDOWN clicks — verify with SetForegroundWindow + real mouse_event at the button's screen position (works; confirmed 2026-08-23). Failed clicks are usually a foreground/z-order problem (terminal on top), not broken buttons.

**AoWSetup.exe itself also carries the AoWx logo** on its embedded 398x450 background — `patch scripts\build_aowsetup_logo.py` (dry-run/--apply/--revert, backup `AoWSetup.exe.bak_logo`, patches the BMP slice at 0x7eda3 in place, composites always from the pristine backup). make_assets.py reads the art from .bak_logo when present. Re-patching AoWSetup requires re-cutting the zip + installer.

**Aux resources embedded from the game dir (NOT in the zip — it's an overlay; vanilla files assumed present in players' installs):** `Start.wav` (splash, same as AoWSetup), `Sfx\Events\NewEvent.WAV` (every popup dialog), `Sfx\Attack\Charm.WAV` (2.7s 16-bit mono, looped during file copy, stopped with PlaySoundW(NULL); **embedded at 0.5x volume — build_installer.py write_quiet_charm() scales samples (CHARM_VOLUME const) into an aux temp dir and passes /DCharmWav; iss falls back to the raw game file when the define is absent**), `Sfx\Events\Mana.WAV` (finish), `X\Documentation\installer fun facts.txt` ("Did you know?" ticker, one line per fact, 7s rotation via SetTimer+CreateCallback; user edits freely — rides into each build). X\Documentation is NOT shipped in the release zip. **Also embedded: `patch scripts\manual_build\NeueHammerUnziale.otf`** — finish page loads it AddFontResourceExW(FR_PRIVATE) and sets FinishedHeadingLabel ("In the first days of the world...") to family **'Neue Hammer Unziale 1'** (the OTF's Windows name-table family), 15pt non-bold (UseUnzialeHeading).

**Splash:** borderless (bsNone) TSetupForm exactly the art size — MUST set `ClientWidth/ClientHeight := ScaleX/Y(398/450)` AFTER `CreateCustomForm(w,h,False,False)` (ctor w/h params are ignored → huge white form otherwise). Art = `assets\setup_bg_aowx.bmp`: AoWSetup's 398x450 BMP (offset 0x7eda3) + AoWx logo (manual `"logo"` base64) registered at scale 0.938 offset (44,23) + AoWSetup's 2-slot button strip (375x22 @0x1028fd — scrub stray pure-white edge pixels) at (11,415) with baked Install/Cancel captions. Buttons = TBitmapImage crops with OnClick → global flag + GSplash.Close (TSetupForm has NO ModalResult in script; no crHand per user). Hover/pressed art (btn_*_hover/_down.bmp: +18% bright / 20% dark shifted 1px) swapped by a 40ms SetTimer poll (GetCursorPos + GetAsyncKeyState(1) — TBitmapImage has NO mouse events; borderless form ⇒ client origin = form Left/Top). Offscreen TNewButtons give Enter/Esc. Regenerate ALL assets with `patch scripts\installer\make_assets.py` (also emits wizard_side.bmp = BPGen.ILB record 10 "IniochRising" crop (36,0,230,372)→164x314, wizard_small.bmp = AoWx.exe icon on #2b2b2b 55x55, aowx_installer.ico; ILB decode: 16bpp 565, transparent key 0x4D2B, magic 0x56509310 — parser adapted from manual_build).

**Wizard:** [Messages] SetupAppTitle=Installer, SetupWindowTitle=Installer - Age of Wonders X (version N), ReadyLabel1/PreparingDesc/InstallingLabel/ExitSetup* say Installer, FinishedHeadingLabel="In the first days of the world...". ALL popups use custom AoWInfo/AoWConfirm dialogs (CreateCustomForm + NewEvent SFX — plain MsgBox would play Windows sounds). Type page: no sub-desc, registry/PBEM note below radios. **Radio-circle clipping fix: `CheckListBox.Offset := ScaleX(6)` (indents items INSIDE the list; moving the control's Left does NOT help — circles draw at its client edge).** Dir page: blank default (unless /DIR), "Navigate to..." captions, Steam (`C:\Program Files (x86)\Steam\steamapps\common\Age of Wonders`) / GOG (`C:\GOG Games\Age of Wonders`) fill buttons in vanilla mode. Perms page: Win11-savefile wording + "can still be done manually" note. Post-install: icacls + RUNASADMIN (HKLM64), MapViewer notice, vanilla-only regedit /s directplay import **verified by RegQueryStringValue(HKLM 32-bit view, DirectPlay\Service Providers\IPX...\Path == dpwsockx.dll)** → IPX/LAN-enabled popup. Finish: Mana SFX, FinishedLabel.AdjustHeight for tight spacing, "Join an active community on the [AoWx Discord]!" link (discord.gg/zn9yARHDFj), single "Close and run AoWSetup." button.

**Testing:** compile with /DDevTest (PrivilegesRequired=lowest, Compression=none) against a small dummy staging; `/SKIPSPLASH=1` (DevTest-only param) bypasses the art splash so tests reach the wizard without input injection. Wizard TNewButtons ignore PostMessage'd BM_CLICK when inactive — post WM_COMMAND (0x0111, wParam=GetDlgCtrlID, lParam=btn hwnd) to GetParent(btn) instead; but only click VISIBLE buttons (hidden Next stays enabled during install). ⚠ User prefers to run interactive install walkthroughs THEMSELVES — deliver the build and let them test rather than UI-driving (2026-08-23). ⚠ UI-driving with SendKeys steals focus from whatever the user is doing — prefer PrintWindow captures (scratchpad shot_window.ps1) which need no focus; /DIR="path" prefdefills the dir page; radios need mouse clicks not arrow keys. Installer is unsigned (SmartScreen may warn).
