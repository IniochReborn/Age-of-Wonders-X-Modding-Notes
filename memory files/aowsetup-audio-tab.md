**Report (a player, 10/24):** audio settings reset every update; not in AoWSetup; AoWSetup SFX too loud, should follow game SFX volume.
**RE:** audio already lives in HKCU\Software\Triumph Studios\Age of Wonders X\Sound (REG_DWORD: SFX Volume / Music Volume 0..100 (Galaxy clamps 100), Sound Effects Enabled, Music Enabled, Sound Quality, Use DirectSound) via AoWEPACK AoWReg.TAoWRegistry. Installer/updater never touch it (updater waits for game exit, no kill). Game writes them ONLY in TMainForm.FormDestroy (AoWx.exe 0x4539E2..0x453A5A) → any unclean exit drops the session's audio changes. Root cause of the player's "reset" not proven — ask whether they quit via menu / crash on exit.
**Game fix** `patch_exe_sound_save_v1.py` (`.bak_soundsave`): TSoundDlg method-table entry CloseClick @0x42116D → wrapper .xtut 0x638810 ('ASV1' zone 0x638800–0x638900) = copy of FormDestroy's sound block then jmp 0x4213DC. TSoundDlg handlers: CloseClick 0x4213DC, MusicVolumeChange 0x4213FC, SFXVolumeChange 0x421410, MusicEnabledChkChange 0x421E14, SFXEnabledChk 0x421E7C. ⚠ .xbfs is FULL (index said 0x60ED00 — stale); .xtut free 0x638900–0x639000.
**AoWSetup** `build_aowsetup_audio_tab.py` (`.bak_audiotab`): .xftx grown 0x2000→0x3000, zone 'AUD1' 0x517000–0x518000; chain head on SettingsBtn 0x4689F4 / SettingsOk 0x469090 (tails → updater caves 0x516520/0x5166A2) + OnCreate method-table dword @file 0x677D2 (tail → Modding wrapper 0x512034). Tab "Audio" (runtime TTabSheet, inserted before Mouse/Hotkeys): 2 TCheckBox + 2 native msctls_trackbar32 (0..100, TBS_TOOLTIPS) children of the sheet HWND (IsWindow re-create + 350 ms one-shot timer). OK writes the 4 DWORDs. AoWSetup volume: winmm!waveOutSetVolume(0, v|v<<16) via GetModuleHandleA/GetProcAddress, at start BEFORE FormCreate (start.wav plays there via TMediaPlayer [form+0x24C]) and after OK. updater_settings script now refuses apply/revert while the audio zone is in front (LIFO). APPLIED, untested. Ship AoWSetup.exe + AoWx.exe.
**v1.1 10/24 (user: slider smeared duplicates while dragging):** VCL TTabSheet answers a child's WM_CTLCOLORSTATIC by sending CN_CTLCOLORSTATIC (0xBD38) back to the child → native trackbar returns 0 → no background brush. Fix: trackbars subclassed (tbproc 0x517A00 via SetWindowLongA GWL_WNDPROC): 0xBD38/0x138 → cached CreateSolidBrush(GetSysColor(15)); else CallWindowProcA(orig). ⭐ Lesson: any native (non-VCL) child window on a VCL parent needs this CN_CTLCOLOR* answer.
