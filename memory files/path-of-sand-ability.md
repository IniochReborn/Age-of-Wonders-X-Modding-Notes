**GOAL (user):** New ability = a copy of **Path of Life** but changes terrain to **Desert/sand** instead of grassland. Name **"Path of Sand"**. Modeled on BXL/Ziggurat's Path of Sand but **rebuilt from scratch in OUR binary** (BXL's version depends on his outer-ring + transport-gate mods and lives in caves that COLLIDE with ours — do NOT copy his bytes). This is a faithful copy of **vanilla Path of Life** (radius 1, surface-only, suppressed on transports — all inherited unchanged) with only the terrain target swapped. Applied 2026-07-23. Backup `AoWEPACK.dll.bak_pathsand`.

**THE VANILLA PATH MECHANISM (AoWEPACK.dll, VA=file+0x55700C00):**
- **Paths are plain TEnhancementAbilities**, NOT a special class. Ids: Decay 0x44, **Life 0x45**, Frost 0x6d. Category word +0x20 = **0x37** (`word[0x557bcfc0]`).
- **Registration** in RegisterPassiveAbilities @~0x557BC960: for each, `CreateEnhancementAbility(eax=id, edx=name AnsiString, cx=category)` @**0x5576601C** (Create obj; obj+0xC=id; LStrAsg(obj+8,name); obj+0x20=cx) → `RegisterAbility(eax=ctrl, edx=obj)` @**0x55750238**. `ebx`=the ability-control throughout.
- **Dispatch** in TAbstractUnit.MovedTo @0x55780328: after a transporter gate (@0x55780416 `test al,al; jnz 0x557804fe` — suppresses ALL paths on transporter armies) and a surface gate (@0x55780421 `cmp byte[field+0x12],0; jne 0x557804b7` — skips Life/Decay underground, jumps to Frost), each path does `mov edx,ID; mov eax,ebx; mov ecx,[eax]; call [ecx+0x148]`(GetAbilityEnabled) then if set: `map.Flood([map_vtable+0xd4], x=field[+0x10], radius=1, unit=ebx, cb=<terrain fn>, level=field[+0x12], y=field[+0x11])`. Life callback ptr=0x557801A4, Decay=0x557801C4, Frost=0x557801E4(+0x5578024C).
- **Terrain callback** (ECX=&terrain byte, EDX=field, RET 4): Life @0x557801A4 = `movsx eax,[ecx]; if ax==6(Ice) or ax==0(Water) skip; if field[+0x12]!=0(underground) skip; else mov byte[ecx],1(Grass)`. Decay identical → 5(Wasteland). **Terrain bytes:** 0 Water,1 Grass,2 Desert,3 Snow,4 Steppe,5 Wasteland,6 Ice,9 Lava,C Dirt (see [[bxl-reference]]).

**OUR IMPLEMENTATION — 4 pieces in free exec cave space @0x5580F3A0+ (after the night-vision caves @0x5580F200-399; CODE section, huge zero gap to ~0x558E7918):**
- **name** "Path of Sand" AnsiString @0x5580F3A0 (`FFFFFFFF|0C000000|"Path of Sand"|00`; chars ptr 0x5580F3A8).
- **cave_sand_cb** @0x5580F3C0 (30B) = exact clone of Life's callback with the terminal `mov byte[ecx],1`→`mov byte[ecx],2` (Desert). Emulation-verified: grass/steppe/snow→Desert, Water(0)/Ice(6)/underground skipped, ret 4 balanced.
- **cave_sanddispatch** @0x5580F400 (79B) = clone of Life's dispatch block (id 0x45→**0x9F**, callback 0x557801A4→0x5580F3C0, radius 1 kept) + re-emit `mov edx,0x6d` + `jmp 0x557804BC`. **Hook: @0x557804B7** (Frost's `mov edx,0x6d` = `BA 6D 00 00 00`) → `jmp 0x5580F400`. Sand is checked as an independent 4th path right before Frost; preserves ebx/ebp (Flood/GetAbilityEnabled are callee-save).
- **cave_sandreg** @0x5580F480 (41B): re-issue Frost's displaced `call 0x55750238`, then Create(0x9F, name, cat)+RegisterAbility(Sand). **Hook: @0x557BC9E9** (Frost's `call 0x55750238`) → `jmp 0x5580F480` → back to 0x557BC9EE.

**id 0x9F** = a free slot in the vanilla range (BXL's list; our mod adds no other abilities). A collision would raise a LOUD "Ability already registered" at startup (safe failure → bump id).

**REBASE CRASH — FIXED & CONFIRMED 2026-07-23 (cave_sandreg + cave_sanddispatch made PIC-safe; user verified reliable startup across many launches).** ROOT CAUSE of an intermittent **"Runtime error 216 at 00003924" at EXE STARTUP** (game starts one launch, fails the next): cave_sandreg (runs at startup during RegisterPassiveAbilities) used a BARE ABSOLUTE `mov edx,0x5580f3a8` (the name-string ptr). AoWEPACK.dll load base VARIES between launches (rebasing — seen at 0x01170000; likely a package-load-order conflict at the 0x55700000 preferred base). At a rebased base the un-relocated absolute pointed to garbage → CreateEnhancementAbility's LStrAsg on a bad string ptr faulted. cave_sanddispatch had the same latent bug (`push 0x5580f3c0` callback + `mov eax,[0x558fa040]` map global) → would've crashed terraforming at a rebased base. **FIX: rewrote both with the PIC delta-trick** (the pattern our slayer caves already use): `call $+5; pop reg; sub reg, <pop's preferred VA>` → reg = load delta; then `lea edx,[reg+0x5580f3a8]` (name), `mov cx,[reg+0x557bcfc0]` (cat), `lea eax,[reg+0x5580f3c0];push eax` (callback), `mov eax,[reg+0x558fa040]` (map). delta reg = eax in reg-cave (before the id load), edi in dispatch-cave (edi is dead in MovedTo). cave_sanddispatch now 94B @0x5580F400, cave_sandreg 53B @0x5580F480 (same addrs/hooks; cave_sand_cb @0x5580F3C0 unchanged, referenced via delta). Verified: emulated delta at rebased base 0x01170000 → correct offset; precise audit → 0 bare-absolute derefs across ALL session caves. **LESSON (critical): any cave that DEREFERENCES an in-image absolute (`mov r,[0x55..]`, `mov r,0x55..addr`, `push 0x55..addr`, bare `[disp32]`) is a LATENT REBASE CRASH — the loader only relocates the game's own refs, not ours. Use the PIC delta-trick for data, rel32 for calls/jmps (already PI). Night-vision + true-seeing caves audited clean; older caves use PIC too.** Backup `AoWEPACK.dll.bak_sandpic_pre`.
