TVortex (spell VMT 0x5579DE1C, target-pick 0x557A18A4 creates TVortexTE VMT 0x5579DD44 via ctor 0x557A10C0). Target must be terrain byte [field+0x14] == 0 or 0xA (CanTarget 0x557A1808/0x557A1850). At target pick the army on the hex is snapshotted into [TE+0x2C] (0x5578C834: x/y/z, owner byte, unit-id list); Validate 0x557A1128 requires that snapshot to still resolve (0x5578B820: same hex, same owner, every id still present).

TVortexTE.Execute 0x557A13CC (eax=TE, edx=unit, ecx=phase): phase 0 charges the cost, plays the effect/sound, creates a TAnimation (class 0x557FAEA0, paint proc 0x557A1178) and returns. Damage happens only on phase 0x50 ('P'), delivered when the animation finishes (TAnimation 0x557FB5C8 → [map+0x28].[vmt+0x6C], an engine-dll import thunk — shared with TTornadoTE 0x557A0796). Per unit of the snapshotted army: skip if GetMovementTypes ([TAbstractUnit vmt+0xE8] = 0x5577FFD0 → 0x5574F764) has bit value 2 = Flying (ability 1) / Wind Walking (0xA5) / Floating (0x3B); else damage rating = 7 if ability 2 Swimming enabled ([vmt+0x148], item-aware), else 10 if 0x17 Sailing, else 0. Roll = TAbstractUnit.ExecuteDamageRole 0x55781AC4 (attack 8 vs Defense, type 0x80 physical; vanilla roll 0x55725EAC: hit chance clamp(50+10*(8-DEF),10,90)%, 1..rating damage), clamped to HP, applied via [vmt+0xE4]. Walking passengers, Water Walking (0xA4) and Liquid Form (0xA6) units take NOTHING — vanilla design, not a bug. Movement-type bit table 0x5574F8FC: 1 Walking(0), 2 Flying group, 4 Swimming(2)/Sailing(0x17)/WaterWalking(0xA4)/LiquidForm(0xA6), 8 Forestry(3|0x9D), 0x10 CaveCrawling(4|0x9D), 0x20 Mountaineering(5|0x9D), 0x40 FireImmunity(7|0xA3), 0x80 Tunneling(0x2A).
