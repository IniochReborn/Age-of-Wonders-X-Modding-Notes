**GOAL:** Editor (AoWDevX.exe) SFX preview buttons (units/abilities/spells SFX windows) play no sound. User wants them working.

**ROOT CAUSE (confirmed):** The editor loads all sound code (imports Sound.PlaySample, Sound.TSFXLibrary.Play, PlaySong from SoundP.dpl) and the preview handlers call them (SFX preview @AoWDevX 0x40F7A0 calls TSFXLibrary.Play thunk @0x4024A8), BUT the editor NEVER calls `Sound.InitializeSoundSystem`/`Galaxy.InitializeGalaxy` — the game (AoWx.exe) does at startup. So the sound-system object is nil and every play is a silent no-op.

**GAME INIT (AoWx.exe FUN_004521f4 / @0x421c0e):** `Sound.InitializeSoundSystem("Galaxy", &settings)` then SetMusicVolume/SetSFXVolume. Settings = 24-byte struct, mostly ZERO except byte[0]=5 and dword[4]=0x5622 (22050 Hz sample rate). InitializeSoundSystem(eax=name string, edx=&settings). It creates the sound system, calls Activate->InitializeGalaxy (loads galaxy.dll)->SetSoundSettings. Window handle at settings+0xc; if 0 -> GetActiveWindow. SoundP.dpl @imagebase 0x55400000: InitializeSoundSystem @0x55406684, SetSFXVolume @0x55406870, SetMusicVolume @0x554067A8; sound-system-instance global @0x5540c02c (nil until init).

**FIX APPLIED (v1, lazy-init via thunk redirect):** Backups `HSEPack.dpl.bak_sfx`, `AoWDevX.exe.bak_sfx`.
- Cave @**0x5561AE00** in HSEPack.dpl (98 B, free zero space after the dialog caves): `pushad`; if `[0x5540c02c]==0` build the 24-byte settings struct on stack {byte0=5, dword4=22050, rest 0} and `InitializeSoundSystem(eax=@"Galaxy" PIC literal, edx=&struct)` via `mov ecx,0x55406684; call ecx`; `popad`; `jmp [0x432CDC]` (the editor's real TSFXLibrary.Play IAT slot). Cross-module absolutes (SoundP 0x5540xxxx, editor IAT 0x432CDC) work at fixed bases; "Galaxy" string PIC-addressed (rebase-safe for HSEPack). Emulation-verified (both paths, regs preserved, stack balanced).
- AoWDevX.exe TSFXLibrary.Play thunk @**0x4024A8** (`ff25 dc2c4300`) -> `e9 <rel to cave> 90` (jmp 0x5561AE00). So every TSFXLibrary.Play call inits-if-needed first.

**TEST RESULT (2026-07-22): FIX DID NOT WORK, REVERTED.** Added a diagnostic MessageBeep (@HSEPack IAT 0x55630614) to the cave and redirected ALL THREE editor sound thunks (TSFXLibrary.Play 0x4024A8, PlaySample 0x4024B0, PlaySong 0x4024B8) each to a beep+init cave (0x5561AE00 / AE80 / AF00). User clicked SFX preview -> **NO BEEP at all**. Conclusion: **the SFX preview button does NOT call any of the 3 game sound-play functions via the editor's IAT thunks.** So "init the audio device" is NOT the cause — the click never reaches a play call. Likely deeper causes: (a) the preview handler is stubbed/no-op; (b) it plays via a SoundP.dpl-INTERNAL path (e.g. the TSFXManagerComboBox control's own preview) invisible to editor-side thunk hooks — would need to hook the SoundP function ENTRIES (0x55406048 TSFXLibrary.Play / 0x554062E4 PlaySample) which also affects the game; or (c) the SFX library isn't loaded in the editor so the SFX object is nil and the play is skipped (note 0x40F7A0's `test ebx,ebx; je skip` where ebx=the SFX object). SHELVED — editor convenience, below the level a clean binary patch reaches. Reverted via HSEPack.dpl.bak_sfx + AoWDevX.exe.bak_sfx (both restored 2026-07-22; .bak_sfx files can be deleted).

**SHELVED 2026-07-22 — DEFINITIVE ROOT CAUSE FOUND, all changes reverted, all `.bak_sfx*` backups deleted.** The preview handler **AoWDevX.exe @0x40F7A0** DOES wire up the play call (`mov eax,ebx; call 0x4024a8` = TSFXLibrary.Play thunk), but it is gated: `xor ebx,ebx` (SFX object defaults nil) -> switch on SFX category loads ebx from a category field -> **`test ebx,ebx; je skip`** (GUARD 1: nil SFX object) -> `mov al,[edi+0x30]; cmp al,[edi+0x18]; jne skip` (GUARD 2: state/index match). In the editor the SFX object (ebx) is NIL — the editor never loads/instantiates the SFX sample library for that window — so control never reaches the play instruction. This is why NEITHER diagnostic beeped: (a) v1 editor-IAT-thunk redirect, (b) v2 SoundP function-ENTRY detour (0x554062E4 PlaySample / 0x55406048 TSFXLibrary.Play, caves @0x55408000/0x55408040, MessageBeep via HSEPack IAT 0x55630614 — verified genuinely MessageBeep). An entry detour catches ALL callers, so no-beep = the call is never executed. => NOT a sound-device-init problem (that's downstream of a call that never happens); NOT a wrong hook. Real blocker is upstream: making the editor populate the SFX object = load SFX sample resources the editor was never built to load in that context (find load path + supply resource pack + wire object into the field) — open-ended, disproportionate. User agreed to shelve. Nothing patched; game/editor at confirmed-good full-restore-point state.
