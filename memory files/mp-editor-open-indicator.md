Hidden state chars '0'..'7' (1 editor, 2 +asg, 4 second instance). Data: +0xF0 line, +0x120 last count, +0x124 pending, +0x128 name; CODE_OFF 0x140. **Protocol:** poll every 3 s (MP only: TSetupControl.GetRemote on [[0x45A454]]+0x48): CreateFileMappingA(-1,0,2,0,0x20,"AOWED"/"AOWEDASG") + GetLastError ∈ {0xB7 already-exists, 5 access-denied (elevated editor)} → CloseHandle. State 0/1/2. State 2 = editor + ≥1 .asg load this editor session. Hidden chat = 3 chars `\x01`+('A'+[map+0xA5] seated idx)+('0'+state), sent via TGDPlay.SendChatMessage(eax=[[0x45A454]+0x44], edx=0 DPID_ALLPLAYERS, ecx=str) on change + every 10 s while ≠0; receiver table `.xedt+0` (16 bytes) with expiry `.xedt+0x10` (25 s). On transition to 2: plain line "<[TGDPlay+0x28] name> has opened a saved game (.asg) in the editor" (LStrCatN 0x401128 → temp string `.xedt+0x60`). Flicker = PATTERN 0xB765DB96 bit (timeGetTime>>8)&31 → bright/dim; PInd invalidated (`[frame+0x2C]=0`) whenever the 256 ms phase changes and any state ≠0.
**Not covered:** combat taskbar TCPInd (17-px, untouched); vanilla/unpatched clients would show the hidden 3-char line as garbage; editor on another PC invisible; purely informational (client-side, bypassable).
