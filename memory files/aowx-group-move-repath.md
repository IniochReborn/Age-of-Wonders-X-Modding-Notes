## 9/21 late: the last detour cause — origin hexes cost 0 (patch_group_move_origin_cost_v1.py)
- Diagnosis by LIVE COST-GRID READS (`patch scripts/grid_probe.py`: settings [sel+4] +0x20 level grids, +0x1c row
  offsets, 4 B/cell, 0xFFFFFF unvisited; the LAST computed unit's grid survives the hover). 2-unit case straight;
  3-unit case detoured with the rear unit last → grid showed group-mates' ORIGIN hexes at their neighbour's cost.
- Cause: TTacticalCombatUnitHS.CanMoveOn 0x42079C own-hex branch, same-side flag-1 marker → `[result]:=0` (0x42083A)
  discards the terrain cost the pathfinder passed in. Grid ≠ path length → the backward reconstruction
  (AoWE 0x557460B0, "neighbour cost == mine − my step", first hit in direction order 1..6) chains through 0-cost
  hexes → 5-step path with the same grid total as the 3-step line. Vanilla bug.
- Fix: hook 0x42083A → cave 0x43AB00 (36 B) stores the terrain cost `[mc + terrain*16 + overlay + 0x31]` (same
  formula as the part branch 0x420B0C), resumes 0x420841. Next free TCPCK cave **0x43AB40**.
- Pathfinder RE (AoWEPACK): TMoveControl.SetupMove 0x55745AE8 (straight-line greedy estimate 0x55746FEC → bound
  [mc+0x2C], 4095 if the line is blocked), flood = start-lines 0x55745D64 → ProcessHexagon 0x557456F8 (recursive
  line sweep, dir-pair table 0x558E8CF4) → CalculateMovePointLine 0x557455B4 (relax `existing<=new → stop`, stop
  after a hex whose CanMoveOver=0, prune > bound), cost callback 0x557454D8 (terrain table, flag 0x40 → CanMoveOn
  with ecx=state=CanMoveOver of the previous hex), reconstruction 0x557460B0, grid alloc/clear 0x55745184/0x557452A4.
  TMovementHS.CanMoveOn 0x431788 only blocks a dest marker when state==0 (never in the flood).
